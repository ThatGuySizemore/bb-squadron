# Squadron watches; the Helper talks

Status: accepted. Supersedes the optional conversational front door and settings-only storage limits in [ADR-0006](0006-squadron-shows-and-starts.md), and clarifies idle lane state in [ADR-0008](0008-stops-are-states-not-rulings.md).

On 14 Nov 2026, SQD-196 and SQD-207 put observation in Squadron's code and conversation in one optional Helper thread shared across the BB install. The Helper uses `bb squadron` to take the same actions as the board. It never polls. Lanes work without it. A notification grants no owner approval, including for an `accept:owner` merge.

The board watcher discovers every BB project and derives its Needs you even when no page is open. The Linear poller keeps those projects current, retaining its existing backoff. Other trackers keep their existing read caches. A project read failure produces a safe Setup line and does not clear earlier items it cannot check. Background observation does not fetch live agent steps.

New Needs you items enter one batch across projects. Each line names the project, kind, spec or ticket, one-line text and link in Owner words, using the same formatter as `bb squadron needs`. New arrivals move the quiet deadline to two minutes after the last arrival, capped at ten minutes after the first. Delivery uses the SDK's `queue-if-active` mode. A missing Helper is harmless; an undelivered batch waits and retries. A failed send remains pending.

Plugin storage retains reported item keys, pending lines and deadlines, and the last observed landing state per lane solely for delivery. Reported keys clear when a successful observation establishes that the item cleared, so a returning item is new. A failed read cannot establish a clear. Pending items that clear before delivery are removed. Successful queued sends count as delivered. A restart retains the batch deadline, rechecks pending Needs you before delivery, and does not replay reported items. The SDK send and storage write are separate operations; this does not claim transactional exactly-once delivery across a process crash between them.

A lane observed underway that later has a merged PR or a Landed spec adds one Landed line to the same batch. Landed is an event, not Needs you. Initial historical landings form a baseline and do not wake the Helper. A reported landing never repeats. Ticket moves, PR opening or readiness, and checks do not wake it.

An idle Lead's latest `turn/completed` event with status `completed` supplies the quiet clock through its event-row `createdAt`, in epoch milliseconds. A generic thread `updatedAt` is not an idle timestamp. SDK interruptions, failed turns, the board or CLI's fixed Stop request, and missing or unreadable lifecycle evidence retain Stopped. A normal completed turn stays Flying, and after five idle minutes with no running workers or background work, it adds a Question, "The Lead is waiting on you", linking the Lead. Landed lanes and owner merge waits never receive that quiet Question. The board and notification use the same derivation. No assistant prose is interpreted as an approval or a stop ruling.

SQD-207 provides observation and delivery, not the daily summary. The board observation callback and shared line helpers can support SQD-211 without another tracker poller. Tests drive the real plugin through the SDK fake host and fake timers, including unattended discovery, batching, reload, clears, landings and quiet-Lead exclusions. Live BB delivery remains a separate integration check.
