# Clean up after landing is opt-in, and BB does the deleting

Landed lanes kept every worker's worktree, and on WordWell each held 4–7 GB. BB removes a worktree five minutes after the last thread in its environment is archived, but Squadron never archived workers, so nothing triggered it.

Decision (the owner, 15 Nov 2026: "Only projects that turn it on (WordWell on)"): a project opts in with a `## Clean up` section set to `After landing` in `docs/agents/squadron.md`. Without it Squadron archives nothing. Deleting is a held action, so it is per project and per owner choice, never a default.

Squadron only archives. It archives a worker thread of a landed lane (merged PR) when the thread is idle, its worktree has no uncommitted changes and its HEAD is on a remote-tracking branch, all read from Git without network access or writes. It never calls `bb environment cleanup` and never touches planning threads or the Helper. A worker that fails a check is kept and listed under Needs you. The watcher does this on its pass; a board or CLI read never changes a thread.

Amended 19 Nov 2026 (the owner, relayed by the WordWell Helper: "After a spec is fully landed and saved, also archive its lead thread, and turn tidy-up on for the BB Squadron project too"). BB's PR panel watches the branch of every environment that isn't archived, about 3 GitHub GraphQL points each check, so landed Leads kept using the hourly allowance. Once the spec's PR is merged and the spec is Done on its tracker (no open tickets; a spec that merged only part of its tickets keeps its Lead), Squadron also archives the Lead's review threads, any worker in the Lead's worktree and then the Lead, last. All of the lane's threads must be idle, and the Lead's worktree passes the same Git-only saved-work checks as a worker. A Lead that fails a check is kept and listed under Needs you, and its review threads stay with it. Squadron still only archives; BB removes the worktree after its own grace period.
