# Planning threads

The board's planning buttons call `planning.start({ projectId, issueId?, step? })` from the BB app: **New spec** (no issue), **Plan** on an Open issue, **Resume planning** on a Shaping spec with an open planning thread, and **Plan tickets** (`step: "tickets"`) on a Shaping spec that lacks its tickets or its ready label. The server opens a visible thread in that project's default checkout, and the board opens it beside itself.

The first message points at the bundled `squadron-planner` skill. It carries the tracker (the Scope's name for Linear), routes from `docs/agents/squadron.md` and the seed issue's identifier, ID, URL, title and description. Tracker fields are quoted as data. New spec asks for `grill-with-docs`, `to-spec` and `to-tickets` from nothing; Plan tickets asks for `to-tickets` on the existing spec and its `ready-for-agent` mark. The skill reads the current repo rules and routes, runs `grill-with-docs` with the owner, and chooses the kind of work using `GLOSSARY.md`. It publishes one-piece work as a Work item with no parent spec and no child tickets, skipping `to-spec` and `to-tickets`. Multi-ticket specs continue through `to-spec` and `to-tickets` as written in Matt's installed plugin. Tickets and work items get route labels from project settings. The agent publishes with its own verified tools as `docs/agents/issue-tracker.md` says.

A second Plan, Resume planning or Plan tickets on the same issue finds its active planning thread through BB's plugin metadata, even after the plugin reloads or the thread is renamed. Archived or deleted threads are left alone and a new one opens. New spec always starts a new thread.

The board reads the same metadata: a spec with an open planning thread stays in Shaping with Resume planning, even when its label and tickets would make it Ready. A work item with an open planning thread stays in Open issues with Plan, which reopens that thread. Archiving the thread ends planning. A work item becomes Ready with `ready-for-agent` and no hold. A spec needs that label and an open, unblocked ticket that is not held. The plugin stores no planning records and has no Linear write tools.

## Starting work

The Helper starts a work item only through `bb squadron start <id>`. Squadron starts its standalone lane thread, which runs `implement`. The Helper never spawns this work as a child thread. A spec lane uses a Lead and workers through `implement-spec`. Both kinds remain subject to House rules, approvals, holds and one final review. An `accept:owner` merge waits for the owner. Historical ADR-0010 describes only the spec lane; this is its current work-item clarification under SQD-237.
